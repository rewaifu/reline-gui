# Reline Web

[English](README.md) · **Русский**

Браузерный редактор **конвейеров обработки изображений Reline**. Вы собираете цепочку нод —
прочитать папку, увеличить нейросетевой моделью, повысить резкость, наложить растр, изменить
размер, поправить уровни, сменить цветовое пространство, записать результат, — проверяете её и
запускаете на раннере Reline по WebSocket. В браузере ничего не обрабатывается: страница —
статический сайт, который правит JSON-конфиг и разговаривает с раннером.

- **Стек нод.** Добавление, перетаскивание, включение и выключение, переименование, смена типа
  ноды, сворачивание. С большими конфигами удобно: тулбар со «свернуть все» и меню «+» с поиском,
  необязательная панель-оглавление.
- **Форма и справка у каждой ноды.** Ползунки, списки и автодополнение путей (папки и веса берутся
  у раннера, модели для апскейла — из базы моделей) и справка на русском и английском.
- **Диагностика на лету.** Конфиг проверяется по мере правки; нода с проблемой помечена, а запуск
  с ошибкой заблокирован.
- **Пресеты и JSON.** Готовые пресеты (Default, Mangascale, Default color, Heavy color), свои
  пресеты и вкладка «Код»: читать, править, копировать, импортировать и экспортировать конфиг.
  Старые плоские конфиги импортируются и переносятся в новый формат.
- **Запуски.** Старт, этапы, скорость и ETA, остановка, переподключение и возврат к прогону,
  который ещё идёт на раннере. Протокол — в [WS_API.md](WS_API.md).
- **Плагины.** Установка по ссылке: новые типы нод, интерфейс, хуки конвейера, методы раннера.
  Вместе с редактором идёт каталог проверенных плагинов. См.
  [docs/PLUGINS.ru.md](docs/PLUGINS.ru.md).
- **Русский и английский** интерфейс; работает на телефоне (две панели и нижний переключатель).
- **Падает мягко.** Экран сбоя сохраняет ноды; сторож ловит зависшую реактивность;
  `?plugins=off` запускает редактор без плагинов.

## Быстрый старт

Нужны Node.js ≥ 24 и [pnpm](https://pnpm.io) 12 (точная версия закреплена в `package.json`).

```bash
pnpm install
pnpm dev          # http://localhost:3000
```

Чтобы что-то выполнить, нужен раннер. Адрес задаётся query-параметром `api`:

```
http://localhost:3000/?api=ws://127.0.0.1:8000/run
```

(`http(s)://` заменяется на `ws(s)://`; без параметра берётся адрес из вкладки «Запуск», затем
`ws://127.0.0.1:8000/run`.) Правка, пресеты, импорт и экспорт работают и без раннера.

### Команды

| Команда               | Что делает                                                            |
| --------------------- | --------------------------------------------------------------------- |
| `pnpm dev`            | dev-сервер Vite на порту 3000                                         |
| `pnpm build`          | статический сайт в `dist/client` (относительные пути: любой хостинг)  |
| `pnpm serve`          | локально отдать production-сборку                                     |
| `pnpm lint`           | `oxlint --type-aware --type-check` (правила Solid включены)           |
| `pnpm typecheck`      | `tsc --noEmit`                                                        |
| `pnpm test`           | Vitest (jsdom)                                                        |
| `pnpm format`         | `oxfmt`                                                               |
| `pnpm plugin:build`   | собрать плагин Config sequence и обновить каталог плагинов            |
| `pnpm plugin:pin`     | опубликовать пример плагина без сборки в `public/plugins/examples/`   |
| `pnpm plugin:catalog` | пересобрать `public/plugins/index.json`                               |
| `pnpm sdk:exports`    | пересоздать список экспортов Solid, на который опирается SDK плагинов |

Прежде чем считать правку готовой, запустите `pnpm lint`, `pnpm typecheck`, `pnpm test` и
`pnpm build`.

## Конфиги

Конфиг — JSON-объект со списком нод; у каждой ноды есть `type` и `options`:

```json
{
  "nodes": [
    {
      "type": "folder_reader",
      "options": { "path": "/data/raws", "mode": "gray", "recursive": false }
    },
    {
      "type": "upscale",
      "options": {
        "model": "4x_dwtp_ds_moesr_v2",
        "dtype": "F32",
        "tiler": "exact"
      }
    },
    {
      "type": "folder_writer",
      "options": { "path": "/data/out", "format": "png" }
    }
  ]
}
```

Встроенные типы нод: `folder_reader`, `upscale`, `sharp`, `resize`, `screentone`, `level`,
`cvt_color`, `hyst_norm`, `noise`, `folder_writer`. Служебное состояние интерфейса (флаг «модель из
базы», имена нод, данные плагинов) раннеру не уходит: вкладка **«Код»** показывает ровно то, что
будет отправлено.

### Модели

Модели для апскейла, которые не ваши, выбираются из базы моделей —
[`https://mdb.yor.ovh/v1/files`](https://mdb.yor.ovh/v1/files). Список кэшируется в браузере на
шесть часов; выбор модели добавляет в запуск шаг загрузки, а нода апскейла хранит только короткое
имя модели.

## Плагины

Вкладка **«Плагины»** ставит плагин по ссылке на его `plugin.json` или из встроенного каталога
**«Проверенные плагины»** (свёрнут, с поиском). Перед установкой редактор показывает права плагина
и хеш его кода. Каталог — это `public/plugins/index.json`, он собирается из манифестов в
`public/plugins/*/`.

Чтобы написать свой, начните с [docs/PLUGINS.ru.md](docs/PLUGINS.ru.md) (по-английски —
[docs/PLUGINS.en.md](docs/PLUGINS.en.md)). Примеры: `examples/sequence` (в каталоге: несколько
конфигов подряд) и `examples/writer-suffix` (плагин в песочнице-воркере, в каталог не входит).

## Устройство проекта

```
src/
  App.tsx, Document.tsx      корень приложения и предотрисованная оболочка документа
  routes/workspace/          рабочее пространство из трёх колонок (оглавление · стек · настройки)
  components/                карточки нод, формы, вкладки настроек, UI плагинов, UI-кит (components/ui)
  context/                   хранилище нод: редьюсер, действия, мост для плагинов
  hooks/                     перетаскивание, раскладка колонок, действия над нодами
  lib/
    convert/, nodes/         реестр нод и преобразование конфиг <-> интерфейс
    pipeline/                хуки этапов: импорт, проверка, экспорт, запуск, ws, стор
    ws/, run-client.ts       WebSocket-хаб и клиент запуска
    plugins/                 манифест, загрузчик, рантайм, каталог, воркер-хост
    i18n/                    словари ru/en
  instructions/{ru,en}/      справка по нодам (Markdown)
  nodes/                     определения встроенных нод
sdk/                         SDK плагинов (definePlugin, помощник для Vite)
examples/                    примеры плагинов
public/plugins/              опубликованные плагины и каталог
docs/                        руководство по плагинам (en, ru)
WS_API.md                    протокол раннера
AGENTS.md                    инструкции для ИИ-агентов, работающих с репозиторием
```
