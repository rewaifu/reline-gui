# Плагины Reline

[English](PLUGINS.en.md) · **Русский**

Плагин — один ES-модуль и `plugin.json` рядом с ним. Пользователь ставит его **по ссылке**
на `plugin.json`; редактор показывает, что плагин просит, проверяет хеш кода, сохраняет
установку в `localStorage` и запускает плагин при каждом старте. Плагин может добавлять и
менять ноды, интерфейс, этапы конвейера (импорт, проверка, экспорт, запуск), действия стора
и запросы к раннеру.

## Для пользователя

**Установка.** Вкладка «Плагины» → вставить ссылку на `plugin.json` → «Проверить». Редактор
скачивает манифест и код, считает SHA-384 и показывает карточку: источник, версию, хеш,
где работает плагин и какие права он просит (каждое можно снять). «Установить» — и плагин
работает. Ссылка вида `https://редактор/?plugin=<ссылка на plugin.json>` открывает ту же
карточку; **сам по ссылке ничего не ставится**.

**Каталог.** Под списком установленных — свёрнутый раздел «Проверенные плагины»: список из
`plugins/index.json`, который лежит рядом с редактором (`public/plugins/index.json`). Он
загружается при первом раскрытии, внутри есть поиск (по названию, id, описанию на любом языке,
правам). «Установить» подставляет ссылку записи, открывает ту же карточку и прокручивает к ней;
дальше всё как при ручной ссылке. «Проверенный» значит: запись называет SHA-384 кода, и манифест,
на который она ведёт, обязан его закреплять — иначе установка отказывает («плагин больше не
совпадает с записью каталога»). Каталог — витрина, не шлюз: ставить по ссылке можно и мимо него.
Если файла нет или он битый, вкладка работает, а в разделе будет «Список недоступен» и «Повторить».

**Описание** плагин показывает на языке интерфейса, если автор написал `descriptions.ru` /
`descriptions.en`; иначе берётся `description`, иначе любое из имеющихся.

**Что запоминается.** В `localStorage`: список установленных (`reline-web:plugins`), проверенный
код (`reline-web:plugin-code:<id>` — плагин стартует из кэша, без сети), данные плагина
(`reline-web:plugin:<id>:…`, не больше 256 КБ на плагин).

**Выключение и удаление.** Переключатель у плагина выключает его сразу, без перезагрузки: всё,
что он зарегистрировал (ноды, вкладки, хуки, действия), снимается. Данные плагина остаются.
Узлы его типов остаются в конфиге как есть («орфаны») и оживают, когда плагин включат снова.

**Если что-то сломалось.**

- `?plugins=off` в адресе — безопасный режим: ни один плагин не загружается.
- Если страница зависла (Solid останавливает всю реактивность при любой необработанной ошибке в
  эффекте), оверлей предложит «Выключить плагины и перезагрузить».
- Если прошлый запуск не дошёл до «страница жива» (вкладку убило, страница замёрзла), плагины,
  которые стартовали тогда, выключаются при следующем открытии, и вкладка «Плагины» говорит об
  этом.
- Хук, который 3 раза подряд бросил ошибку, отключается; сбои видны во вкладке «Плагины».

**Ограничить источники.** `localStorage["reline-web:plugins:allow"] = ["https://плагины.example"]` —
тогда ставить можно только оттуда (пусто = откуда угодно, при условиях ниже).

## Быстрый старт

```ts
// src/index.tsx
import { definePlugin } from "@reline/plugin-sdk";

export default definePlugin<"nodes" | "i18n">({
  activate(api) {
    api.i18n.add("en", { name: "Border" });
    api.i18n.add("ru", { name: "Рамка" });
    api.nodes.define({
      type: "acme.border.add", // <id плагина>.<имя>
      label: api.i18n.text("name"),
      defaults: () => ({ width: 8 }),
      // Form, schema, toPure, fromPure, validate… — всё необязательно
    });
  },
});
```

```ts
// vite.config.ts
import solid from "@solidjs/vite-plugin";
import { defineConfig } from "vite";
import { relinePlugin } from "@reline/plugin-sdk/vite"; // sdk/vite.ts в этом репозитории

export default defineConfig({
  plugins: [
    relinePlugin({
      manifest: {
        id: "acme.border",
        name: "Border",
        version: "1.0.0",
        caps: ["nodes", "i18n"],
      },
    }),
    solid(),
  ],
  build: { outDir: "dist", lib: { entry: "src/index.tsx", formats: ["es"] } },
});
```

`vite build` кладёт в `dist/` модуль и `plugin.json` с хешем. Выложите оба по https —
ссылка на `plugin.json` и есть «ссылка для установки».

Без сборки тоже можно: обычный ES-модуль без импортов, `export default { activate(api) {…} }`,
плюс `plugin.json` с хешем (`scripts/pin-plugin.mjs`). Solid берите из `api.solid` / `api.web`.

## Локальная разработка

1. Положите собранный плагин в `public/plugins/<имя>/` репозитория редактора (`plugin.json` и
   модуль рядом) и запустите `pnpm dev`. Ссылка для установки — `http://localhost:3000/plugins/<имя>/plugin.json`.
   Для `localhost` хеш не обязателен, а `http:` разрешён.
2. Вкладка «Плагины» → вставьте ссылку → «Проверить» → «Установить». Или откройте
   `http://localhost:3000/?plugin=<ссылка на plugin.json>`: карточка появится сама, но поставить
   надо вручную.
3. После пересборки хеш меняется: нажмите «Обновить» у плагина (или проверьте ссылку заново) —
   редактор покажет карточку обновления. Версию в манифесте поднимайте при каждом выпуске, иначе
   пользователи с кэшем не увидят разницы.
4. Свой сервер на другом порту работает, если он отдаёт CORS (`Access-Control-Allow-Origin`), а
   модуль лежит на том же origin, что и манифест (на другом origin нужен `integrity`).
5. Что-то сломалось и страница не открывается — `?plugins=off` в адресе.

Сообщения плагина (`api.log`) и сбои хуков видны во вкладке «Плагины».

## Манифест

```jsonc
{
  "id": "acme.border", // a.b[.c…], строчные, [a-z0-9-]; префикс всего, чем плагин владеет
  "name": "Border",
  "version": "1.0.0",
  "api": 1, // поколение API редактора; несовместимые плагины отклоняются
  "description": "…", // одним языком; запасной вариант для всех
  "descriptions": { "ru": "…", "en": "…" }, // необязательно, любой из двух; показывается на языке читателя
  "entry": "border.js", // относительно манифеста
  "integrity": "sha384-…", // обязателен, кроме локального сервера разработки
  "caps": ["nodes", "ui"], // что просит
  "requires": { "acme.base": "1.2.0" }, // другие плагины (id → мин. версия), стартуют раньше
  "sandbox": "page", // или "worker" (см. ниже)
}
```

Правила загрузки: только `https:` (или `http://localhost`); код на другом origin допустим только с
`integrity`; манифест ≤ 64 КБ, код ≤ 1 МБ; без cookie и кэша; выполняется именно тот код, что
был захеширован (импорт из Blob, а не повторная загрузка по ссылке).

**Права (`caps`)**: `nodes`, `ui`, `pipeline`, `store`, `ws`, `i18n`, `storage`, `run`, `config`.
Объект `api` содержит **только** выданные пространства; остальных у него нет.

## API

`activate(api)` вызывается один раз; может быть `async` (до 5 с) и вернуть функцию очистки.
Всё зарегистрированное через `api.*` снимается при выключении плагина. Всегда есть:
`api.id`, `api.version`, `api.solid`, `api.web` (**копии Solid редактора — используйте их**, свой
Solid в плагине не работает с редактором), `api.log(...)`, `api.onDispose(fn)`.

Имена, которыми владеет плагин, начинаются с его id: типы нод `<id>.<имя>`, действия стора
`<id>:<имя>`, методы WS `x.<id>.<имя>`; хуки получают префикс `<id>:` автоматически.

### `api.nodes`

`define(def)` · `patch(type, changes)` · `hide(type)` · `get` · `list` · `create(type)`.
`NodeDef` — единственное описание типа: `defaults()`, `schema` (valibot), `normalize`, `Form`,
`doc`, `toPure`/`fromPure` (как нода превращается в конфиг раннера и обратно), `validate`,
`prepare` (последний шанс изменить ноду перед запуском). `patch` меняет **любой** тип, в том
числе встроенный. Узлы типа, у которого нет определения, не теряются: они хранятся как есть,
а когда определение появляется, их опции приводятся к схеме.

### `api.ui`

- `slot(name, Component, {order})` — `topbar` (строка инструментов над стеком, правая часть:
  бейджи и мелкие кнопки), `stack.footer` (под списком нод), `node.card.header` и
  `node.card.footer` (последние два получают `{ node }`). Каждый вклад в своей границе ошибок.
- `override(id, wrap)` — заменить или обернуть `NodeCard`, `NodeBody`, `AddNodeMenu`:
  `wrap` получает прежний компонент, возвращает новый. Если новый падает при отрисовке,
  рисуется прежний.
- `panelTab({id, label, Component, order, scroll})` — вкладка правой панели (у встроенных порядок
  10–50). Содержимое вкладки плагина панель прокручивает сама (`scroll` по умолчанию `true`);
  `scroll: false` — если вкладка управляет прокруткой сама.
- `kit` — родные контролы редактора как компоненты: `Button` (`variant="primary"`),
  `IconButton` (`icon`, `label` — это и aria-label, и подсказка), `Switch`, `Input`, `Icon`
  (имена значков — `IconName`, например `plus`, `trash`, `pencil`, `arrow-up`, `refresh`, `play`).
  Берите их вместо своих `<button>` и чекбоксов: панель плагина выглядит как остальные вкладки,
  а плотность, размеры под палец и токены берутся из редактора.
- `styles(css)` — глобальный CSS после стилей редактора; можно менять токены (`:root{--color-…}`).
  Свои селекторы ограничивайте своим классом.

Ошибка **внутри эффекта** (не в рендере) останавливает всю реактивность Solid — граница ошибок
её не ловит. Оборачивайте код эффектов в `try/catch`.

### `api.pipeline`

`use(stage, fn, {id, before, after, timeoutMs})` — хук этапа (ниже). `failures()` — сбои ваших хуков.

### `api.store`

`nodes()` (живой стек, реактивен), `dispatch(action)`, `action(type, reducer)` — свои действия,
`observe(fn)`. На узле можно хранить данные: `CHANGE` с `ext: { "<id>": … }` (сливается по ключам);
они едут с узлом в хранилище, в экспорт (`meta.ext`) и в импорт.

### `api.ws`

`method({name, request, response, timeoutMs})` (схемы valibot; имя `x.<id>.<имя>`),
`call(name, data)` — проверка запроса и ответа по схеме, `request`, `on(method, fn)` — пуши
сервера, `open()`. Кадры можно перехватывать хуками `ws.send` / `ws.receive`.

### `api.i18n`

`add(locale, {ключ: строка})`, `text(key, params)` — `LocalText` для меток, диагностик, вкладок,
`t(key, params)` — строка сейчас (реактивна в JSX). Порядок поиска: язык интерфейса → en → любой → ключ.

### `api.storage`

`get/set/remove/getJson/setJson` под префиксом плагина, квота 256 КБ (`set` возвращает `false`).

### `api.run` и `api.config`

`run.start(config)` → `Promise<{ok, cancelled, text}>` по окончании прогона (отклоняется, если
прогон уже идёт), `run.stop()`, `run.phase()`, `run.progress()`, `run.onFinish(fn)`.
`config.analyze(nodes)` → `{config, text, diagnostics, errors}`, `toPure`, `fromPure`, `parse(text)`,
`replaceStack(nodes)`.

### Уровень worker (`"sandbox": "worker"`)

У плагина-воркера урезанный `api`: `id`, `version`, `log(...)` и один хук
`api.pipeline.beforeRun(fn)`, где `fn(config)` возвращает конфиг (или промис с ним). Нет Solid, нет
DOM, нет других пространств. Пишется как обычный ES-модуль — см.
`examples/writer-suffix/writer-suffix.js`:

```js
export default {
  activate(api) {
    api.pipeline.beforeRun((config) => ({
      ...config /* измените что нужно */,
    }));
  },
};
```

## Этапы конвейера

| Этап                     | Вход → выход                      | Когда                                |
| ------------------------ | --------------------------------- | ------------------------------------ |
| `import.parse`           | разобранный JSON → JSON           | вставка/файл конфига, до разбора     |
| `import.sanitize`        | `unknown[]` узлов → `unknown[]`   | любой импорт, до встроенных проверок |
| `validate`               | стек → `Diagnostic[]`             | всегда; **ошибка запрещает запуск**  |
| `toPure.node`            | `PureNode[]`, узел → `PureNode[]` | сборка конфига, на узел              |
| `toPure.config`          | конфиг, стек → конфиг             | сборка конфига целиком               |
| `beforeRun`              | конфиг → конфиг (**async**)       | прямо перед отправкой раннеру        |
| `export.serialize`       | текст, конфиг → текст             | вкладка «Код», копирование, файл     |
| `ws.send` / `ws.receive` | кадр → кадр / `null`              | каждый кадр (кроме хартбита)         |
| `store.action`           | действие → действие / `null`      | каждое действие над стеком           |

Хук ничего не возвращает — значение не меняется (можно менять на месте); возвращает значение нужной
формы — оно подменяет. Неверная форма, исключение, зависание (`beforeRun` — 10 с), промис в
синхронном этапе — сбой: он записывается, хук пропускается, значение идёт дальше. Три подряд —
хук отключается. Порядок — по регистрации, уточняется `before`/`after` (id чужого хука —
`<id плагина>:<id хука>`).

`validate` возвращает `Diagnostic { code, severity: "error"|"warn", message: LocalText, uid?, path? }`.

## Безопасность

**Плагин уровня `page` (по умолчанию) — это код на странице редактора с теми же правами.** Он видит
ваши конфиги и `localStorage`, может слать запросы раннеру (а раннер умеет чистить папки и удалять
исходники). Список `caps` и карточка — это **информирование пользователя**, не песочница: объект `api`
не содержит лишнего, но плагин, который хочет, достанет `localStorage` напрямую. Защита здесь — это
согласие пользователя, закреплённый хеш (то, что одобрено, то и выполняется; подмена кода по ссылке
не пройдёт), разрешённые источники, безопасный режим и откат после сбоя. Ставьте только то, чему
доверяете как коду.

**Плагин `"sandbox": "worker"`** выполняется в Web Worker: нет DOM, нет `localStorage`, нет объектов
редактора. Единственный вход — конфиг прогона, который приходит в его `beforeRun`; единственный
выход — конфиг, который он возвращает. Права ограничены `pipeline` (манифест с другим отклоняется).
Это единственный уровень, где ограничения **принудительны**. Но воркер по-прежнему может ходить в
сеть и видит конфиги, которые ему дали, — изоляция ограничивает, что плагин может _достать_, а не
что он делает с тем, что получил. Хуки других этапов в воркер не вынести: они синхронные и
выполняются внутри `memo`, которое не может ждать сообщение.

## Сборка и публикация

- `relinePlugin()` (`sdk/vite.ts`) подменяет импорты `solid-js` и `@solidjs/web` на чтение из
  `globalThis.__RELINE__` (копии редактора) и после сборки пишет `plugin.json` с SHA-384.
  Список имён лежит в `sdk/host-exports.json`; после обновления Solid: `pnpm sdk:exports`
  (тест `sdk/sdk.test.ts` падает, если список устарел).
- Собранный плагин нельзя форматировать и править руками: хеш закреплён побайтно
  (`public/plugins/**` исключён из `oxfmt` и `oxlint`).
- В репозитории: `pnpm plugin:build` собирает Config sequence и обновляет каталог
  `public/plugins/index.json`; `pnpm plugin:pin` публикует пример без сборки Writer suffix в
  `public/plugins/examples/writer-suffix/` (**вне каталога**); `pnpm plugin:catalog` — только
  пересобрать каталог. CI пересобирает всё и требует, чтобы `public/plugins` не изменился.
- Публикация: любой статический хостинг по https. Для разработки хватит `http://localhost`
  (хеш не обязателен). Обновление — новый `version` и новый хеш; редактор покажет карточку
  обновления и выделит **новые** права.

## Как попасть в каталог

Каталог — это `public/plugins/index.json` в репозитории редактора, и вести его вручную не нужно.

1. Соберите плагин так, чтобы в `public/plugins/<имя>/` лежали модуль и `plugin.json` **с хешем**
   (`relinePlugin()` делает это сам).
2. Допишите описание: `description` и, по желанию, `descriptions: { ru, en }`.
3. `pnpm plugin:catalog` — запись появится в каталоге (id, имя, версия, описания, права, хеш).
4. `pnpm test` проверит, что каталог совпадает с манифестами и что хеш — это хеш реального файла.

Плагины в подкаталогах глубже (`public/plugins/examples/…`) каталог не видит: так держат образцы,
которые нельзя рекомендовать.

## Примеры

### Config sequence (в каталоге)

`examples/sequence/` (собран в `public/plugins/sequence/`, ставится ссылкой
`./plugins/sequence/plugin.json`). Строит пайплайн из нескольких конфигов и запускает их по очереди.

Права: `ui` (вкладка «Последовательность», бейдж «Последовательность 2/4» в строке инструментов над
стеком, виден из любой вкладки), `storage` (шаги переживают перезагрузку), `run` (запуск шага и ожидание его
конца), `config` (чтение, проверка и сборка конфигов шагов), `store` (взять текущий стек как шаг),
`i18n` (ru/en).

- **Шаг** = полный конфиг. Источники: «Добавить текущий стек», «Импорт конфигов…» (несколько
  файлов; читаются тем же импортом, что и вкладка «Код», так что легаси-формат тоже подходит),
  «Заменить текущим стеком».
- **Порядок и состав**: ↑↓, переключатель шага, переименование, «Загрузить в редактор» (шаг
  становится стеком для правки), удаление.
- **Запуск**: идут только включённые шаги, строго по очереди — следующий стартует, когда
  предыдущий закончился. Перед стартом каждый шаг проходит те же проверки, что и обычный запуск
  (`config.analyze`); с ошибкой — шаг `failed`, раннеру не отправляется. «Остановиться на первой
  ошибке» (по умолчанию включено) или идти дальше. «Стоп» останавливает текущий прогон и снимает
  остальные.
- Если прогон уже идёт (запущен из вкладки «Запуск»), шаг не встаёт в очередь за ним, а
  завершается ошибкой.

Интерфейс собран из `ui.kit`, поэтому выглядит как родные вкладки.

Исходник — образец для собственных плагинов: пример использует `createStore`, расщеплённый
`createEffect(compute, apply)`, `ui.slot`, `ui.panelTab`, `ui.styles` и словарь ru/en.

### Writer suffix (только пример)

`examples/writer-suffix/` — образец уровня `worker`: обычный ES-модуль без сборки, в `beforeRun`
дописывает `-sandboxed` к папке каждого writer. В каталог не входит; ставится ссылкой
`./plugins/examples/writer-suffix/plugin.json` (после `pnpm plugin:pin`).

## Тесты плагина

Контракт проверяется против настоящего API: `createPluginApi` + настоящий стек, подменяется только
`runClient` (см. `examples/sequence/sequence.test.tsx`). Для проверки установки есть
`setModuleLoader` и `setWorkerFactory` (jsdom не умеет импортировать Blob и не имеет Worker).

## Чеклист автора

- `id` вида `acme.border`; всё, чем владеет плагин, начинается с него (типы нод, действия `<id>:…`,
  методы WS `x.<id>.…`, ключи `localStorage` — через `api.storage`).
- В `caps` только то, что нужно. Если хватает `pipeline` — делайте `"sandbox": "worker"`.
- Solid — только из редактора (`relinePlugin()` подменяет импорты; без сборки — `api.solid`).
- Каждый эффект: читаемые реактивные значения — в первой функции `createEffect(compute, apply)`;
  внутри `apply` — без чтения реактивного (`untrack`); тело в `try/catch`.
- Большое хранилище не сериализуйте эффектом по всему `store` (тысячи подписок): сохраняйте по
  счётчику изменений.
- Интерфейс — из `api.ui.kit`, цвета и отступы — токены `--color-*`, `--space-*`, `--radius-*`;
  свои селекторы под своим классом; значки без подписи — с `label`.
- Все строки — через `api.i18n` на ru и en; описание плагина — `description` + `descriptions`.
- Для каждой диагностики `validate` — понятный `message` (`LocalText`) и `severity`.
- Версию поднимайте при каждой публикации, пересобирайте хеш, проверяйте обновление «Обновить».
- Тест: контракт против настоящего `createPluginApi` (см. «Тесты плагина»).
